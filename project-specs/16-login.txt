---

# Objetivo da Funcionalidade

A tela de Login é o ponto de entrada da aplicação.

Sua responsabilidade é autenticar o usuário através da API do **TOTVS Datasul** e conceder acesso ao sistema.

Esta tela deve ser extremamente simples, rápida e intuitiva, pois será utilizada diversas vezes ao longo do dia pelos operadores da fábrica.

---

# Objetivo de Negócio

Permitir que usuários autorizados acessem o Plano de Controle CQ.

Após autenticação bem-sucedida, o sistema deve:

* armazenar a sessão do usuário;
* carregar as permissões;
* redirecionar para o Menu Principal.

---

# Usuários

A autenticação será utilizada por:

* Operador
* Líder
* Supervisor
* Inspetor CQ
* Administrador

A autorização será definida pela API do Datasul.

---

```mermaid
flowchart TD

A[Abertura da Aplicação]
```

---

# Objetivos de UX

A tela deve transmitir simplicidade.

O usuário deve conseguir realizar login em poucos segundos.

Não devem existir elementos desnecessários.

A interface deve seguir fielmente o mockup aprovado.

---

# Layout Geral

A tela será centralizada.

O conteúdo ficará verticalmente organizado.

```text
+--------------------------------------+

            LOGO CORTAG

Login

[____________________]

Senha

[____________________]

          Entrar

+--------------------------------------+
```

---

# Estrutura Visual

A tela possuirá apenas quatro elementos principais.

* Logo Cortag
* Campo Login
* Campo Senha
* Botão Entrar

Opcionalmente poderá existir uma pequena versão da aplicação no rodapé.

---

# Cabeçalho

O cabeçalho será composto apenas pelo logotipo da Cortag.

O logotipo deverá permanecer centralizado.

Não utilizar barra superior.

---

# Logo

Utilizar o logotipo oficial da Cortag.

O logo deve possuir boa resolução.

Nunca alterar:

* proporção;
* cores;
* tipografia.

---

# Campo Login

## Objetivo

Identificar o usuário.

Tipo:

Texto.

Placeholder:

```text
Informe seu login
```

Obrigatório.

Ao pressionar ENTER:

Mover foco para o campo Senha.

---

# Campo Senha

## Objetivo

Receber a senha do usuário.

Tipo:

Password.

Placeholder:

```text
Informe sua senha
```

Obrigatório.

Ocultar caracteres digitados.

Ao pressionar ENTER:

Executar Login.

---

# Botão Entrar

Botão primário.

Cor:

Vermelho Cortag.

Texto:

```text
Entrar
```

Ao clicar:

Iniciar autenticação.

---

# Navegação

Origem:

Abertura da aplicação.

Destino:

Menu Principal.

---

# Validações

Antes de enviar:

Login informado.

Senha informada.

Caso contrário:

Exibir mensagem.

Exemplo:

```text
Informe login e senha.
```

---

# Estados da Tela

A tela deverá contemplar:

* Inicial
* Digitando
* Autenticando
* Erro
* Sucesso

---

# Estado Inicial

Campos vazios.

Botão Entrar habilitado.

---

# Estado Digitando

Permitir edição livre.

---

# Estado Autenticando

Desabilitar:

* Login
* Senha
* Botão Entrar

Mostrar indicador de carregamento.

---

# Estado Sucesso

Salvar sessão.

Redirecionar automaticamente.

---

# Estado Erro

Exibir mensagem amigável.

Não limpar automaticamente o campo Login.

Limpar apenas o campo Senha.

# Estrutura Esperada

Request:

```typescript
export interface LoginRequestDTO {
    login: string;
    senha: string;
}
```

Response:

```typescript
export interface LoginResponseDTO {
    token: string;
    usuario: UsuarioDTO;
}
```

Model:

```typescript
export interface Usuario {
    id: string;
    nome: string;
    login: string;
    permissoes: string[];
}
```

# Tratamento de Erros

Possíveis erros:

## Login inválido

Mensagem:

```text
Usuário ou senha inválidos.
```

---

## Erro de comunicação

Mensagem:

```text
Não foi possível conectar ao servidor.
```

---

## Erro inesperado

Mensagem:

```text
Ocorreu um erro inesperado.
```

---

# Loading

Durante autenticação:

Mostrar spinner.

Desabilitar formulário.

Evitar múltiplos cliques.

---

# Segurança

Nunca armazenar senha.

Nunca registrar senha em logs.

Nunca utilizar LocalStorage para dados sensíveis, salvo se definido pela estratégia oficial de autenticação.

Sempre utilizar HTTPS.

---

# Regras de UX

* O foco inicial deve estar no campo Login.
* ENTER no Login move para Senha.
* ENTER na Senha executa Login.
* O botão Entrar deve ser facilmente acessível em tablets.
* Os campos devem possuir altura adequada para toque.

---

# Responsividade

A tela deve funcionar em:

* Tablets 1024×768
* Tablets 1280×800
* Desktop

A interface deve permanecer centralizada.

---

# Critérios de Aceite

A tela será considerada concluída quando:

* O logotipo da Cortag estiver centralizado.
* Os campos Login e Senha estiverem visíveis.
* O botão Entrar executar autenticação.
* O formulário validar campos obrigatórios.
* O sistema exibir loading durante autenticação.
* O sistema exibir mensagens amigáveis em caso de erro.
* O sistema redirecionar ao Menu Principal após sucesso.
* O layout seguir o Design System.
* A interface estiver otimizada para tablets.
