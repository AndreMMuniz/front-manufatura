# Objetivo da Funcionalidade

A tela **Equipes** é responsável pela manutenção das equipes produtivas da fábrica.

Seu principal objetivo é permitir que supervisores e líderes consultem uma equipe existente e realizem a manutenção dos operadores pertencentes a essa equipe.

Esta funcionalidade não cria operadores.

Ela apenas altera o vínculo entre operadores e equipes.

Toda persistência será realizada através das APIs do Datasul.

---

# Objetivo de Negócio

A equipe representa um agrupamento de operadores utilizado na produção.

Cada equipe possui:

* Código
* Descrição
* Turno
* Lista de Operadores

O usuário poderá:

* consultar uma equipe;
* visualizar seus operadores;
* adicionar operadores;
* remover operadores;
* salvar alterações.

---

# Perfil de Usuário

Esta funcionalidade será utilizada principalmente por:

* Supervisor
* Líder
* Administrador

Operadores comuns normalmente não possuirão acesso.

A validação de permissões será realizada pelo backend.

# Objetivo do Painel

Permitir que o usuário altere rapidamente a composição da equipe.

Toda alteração ocorre apenas dentro do painel.

A tela principal permanece bloqueada enquanto o painel estiver aberto.

# Comportamento do Painel

Ao abrir:

Consultar lista de operadores.

Marcar automaticamente aqueles pertencentes à equipe.

Permitir:

* adicionar;
* remover;
* pesquisar.

---

# Fluxo do Usuário

1. Acessa Equipes.

2. Informa equipe.

3. Sistema consulta API.

4. Dados são carregados.

5. Usuário visualiza operadores.

6. Clica Alterar.

7. Painel lateral abre.

8. Pesquisa operador.

9. Marca ou desmarca operadores.

10. Salva.

11. Painel fecha.

12. Tela principal é atualizada.

---

# Estados da Tela

A tela deverá contemplar:

Inicial

Carregando

Equipe carregada

Equipe vazia

Erro

Salvando

Sucesso

---

# Estado Inicial

Nenhuma equipe carregada.

Apenas os campos disponíveis para consulta.

Lista vazia.

Botão Salvar desabilitado.

---

# Estado Carregando

Durante consulta da equipe:

* loading visível;
* botões bloqueados;
* impedir múltiplas consultas simultâneas.

---

# Estado Com Dados

Campos preenchidos.

Lista carregada.

Botões habilitados.

---

# Estado Sem Dados

Caso a equipe não exista:

Limpar todos os campos.

Exibir mensagem amigável.

Não exibir erro técnico.

---

# Estado Salvando

Ao salvar:

Mostrar indicador de progresso.

Desabilitar botões.

Aguardar retorno da API.

---

# Estado de Erro

Qualquer falha deverá gerar mensagem amigável.

Exemplo:

"Não foi possível carregar os dados da equipe."

Nunca apresentar mensagens da API diretamente ao usuário.

---

# Objetivos de Performance

A abertura da tela deve ser imediata.

A consulta da equipe deve ocorrer apenas quando necessário.

A lista de operadores deve suportar grande quantidade de registros sem perda perceptível de desempenho.

Utilizar virtualização ou paginação caso a quantidade de operadores torne a renderização custosa.

---

# Regras Gerais

* Nunca permitir edição diretamente na lista principal.
* Toda manutenção ocorre pelo painel lateral.
* Não permitir duplicidade de operadores.
* Sempre manter sincronismo entre painel e tela principal.
* A interface deve permanecer simples, limpa e otimizada para uso em tablets.

# Casos de Teste

## CT001 — Consultar equipe existente

Dado que o usuário informa uma equipe válida.

Quando confirma a consulta.

Então o sistema deve carregar descrição, turno e operadores.

---

## CT002 — Consultar equipe inexistente

Dado que o usuário informa uma equipe inexistente.

Quando confirma a consulta.

Então o sistema deve exibir mensagem amigável e manter tela sem dados.

---

## CT003 — Abrir painel de alteração

Dado que uma equipe está carregada.

Quando o usuário clica em Alterar.

Então o painel lateral deve abrir com os operadores disponíveis.

---

## CT004 — Marcar operador

Dado que o painel está aberto.

Quando o usuário marca um operador.

Então o operador deve permanecer selecionado.

---

## CT005 — Desmarcar operador

Dado que o painel está aberto.

Quando o usuário desmarca um operador.

Então o operador deve sair da seleção.

---

## CT006 — Selecionar todos

Dado que o painel está aberto.

Quando o usuário marca Todos.

Então todos os operadores visíveis devem ser selecionados.

---

## CT007 — Pesquisar operador

Dado que o painel possui operadores carregados.

Quando o usuário digita no campo de busca.

Então a lista deve ser filtrada por código ou nome.

---

## CT008 — Manter seleção durante pesquisa

Dado que um operador foi selecionado.

Quando o usuário pesquisa outro operador.

Então a seleção anterior deve permanecer.

---

## CT009 — Salvar alterações

Dado que o usuário alterou operadores.

Quando clica em Salvar.

Então o sistema deve persistir as alterações, fechar o painel e atualizar a lista principal.

---

## CT010 — Voltar sem salvar

Dado que o usuário alterou operadores.

Quando clica em Voltar.

Então o sistema deve solicitar confirmação antes de descartar as alterações.
