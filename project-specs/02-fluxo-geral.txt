# Fluxo Geral da Aplicação

## Objetivo

Este documento descreve o fluxo funcional completo da aplicação **Plano de Controle CQ** da Cortag.

Seu objetivo é fornecer aos agentes de IA uma visão completa da navegação entre as telas, permitindo compreender como cada funcionalidade se relaciona dentro do sistema.

Este documento não substitui a documentação individual de cada tela. Ele apenas define como o usuário percorre a aplicação.

---

# Visão Geral

A aplicação foi projetada para utilização em ambiente industrial, com foco em simplicidade, rapidez e mínimo número de interações.

O usuário deverá conseguir executar todas as operações com poucos toques na tela.

A navegação deve ser intuitiva e sempre permitir retornar ao passo anterior.

# Menu Principal

Após autenticação, o usuário acessa o Menu Principal.

O menu representa o ponto central da aplicação.

Todas as funcionalidades são acessadas a partir dele.

Itens disponíveis:

* Equipes
* Centro de Trabalho
* Reporte de Operações
* Reporte de Paradas
* Plano de Controle CQ
* Sair

# Fluxo de Retorno

Em todas as telas deve existir um mecanismo claro para retorno.

Ao acionar o botão **Voltar**, o sistema deverá retornar para a tela imediatamente anterior sem perda de contexto, sempre que possível.

Quando houver alterações não salvas, o sistema deverá solicitar confirmação antes de descartar os dados.

---

# Fluxo de Saída

Ao selecionar **Sair**, o sistema deverá:

1. Encerrar a sessão do usuário.
2. Limpar dados temporários.
3. Retornar para a tela de Login.

---

# Fluxos Assíncronos

Sempre que houver comunicação com a API do Datasul:

* Exibir indicador de carregamento.
* Bloquear ações conflitantes.
* Exibir mensagens de erro em caso de falha.
* Atualizar a interface após sucesso.

---

# Estados de Navegação

Cada tela deve considerar os seguintes estados:

* Inicial
* Carregando
* Com Dados
* Sem Dados
* Erro
* Salvando
* Sucesso

Nenhuma operação deve ocorrer sem feedback visual.

---

# Regras Gerais de Navegação

* O Menu Principal é o ponto central da aplicação.
* O usuário nunca deve ficar preso em uma tela.
* Toda tela deve possuir ação de retorno.
* Funcionalidades secundárias devem utilizar painéis laterais ou modais sempre que possível.
* Evitar abrir novas páginas quando uma interação puder ocorrer na tela atual.
* Manter a navegação simples e previsível para operadores em ambiente industrial.

---

# Dependências entre Funcionalidades

Algumas funcionalidades dependem de informações previamente selecionadas.

Exemplos:

* O Reporte de Operações depende do Centro de Trabalho.
* O Plano de Controle CQ depende de uma Ordem de Produção ativa.
* A Inspeção de Processo depende da geração do roteiro.
* A Digitação de Exames depende da inspeção selecionada.

Essas dependências devem ser respeitadas durante a implementação.

---

# Checklist

Antes de implementar qualquer funcionalidade, verificar:

* O fluxo desta tela está documentado.
* A navegação respeita este documento.
* Existe caminho de retorno.
* Existem estados de loading e erro.
* O fluxo é compatível com uso em tablets.
* O usuário consegue concluir a operação com o menor número possível de interações.
