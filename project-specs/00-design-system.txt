# Design System — Plano de Controle CQ (Cortag)

## Objetivo

Este documento define o Design System oficial do sistema **Plano de Controle CQ** da Cortag.

Todas as telas, componentes e funcionalidades implementadas por agentes de IA (Codex, BMAD, Claude Code, OpenCode ou similares) devem seguir rigorosamente este documento para garantir consistência visual, boa experiência do usuário e padronização do código.

O sistema será utilizado principalmente em **tablets industriais**, portanto todas as decisões de interface devem priorizar usabilidade em dispositivos touch.

---

# Identidade Visual

## Cliente

Cortag

## Segmento

Ferramentas e equipamentos para construção civil.

## Objetivo Visual

A interface deve transmitir:

* Simplicidade
* Robustez
* Agilidade
* Clareza
* Ambiente industrial
* Facilidade de operação

Evitar interfaces poluídas ou excesso de informações.

---

# Paleta de Cores

## Cor Primária

Utilizar o vermelho institucional da Cortag como cor principal para:

* Botões primários
* Destaques
* Links ativos
* Cabeçalhos
* Elementos de ação

## Cor Secundária

Branco.

Utilizar como cor predominante do fundo.

## Cores Neutras

Cinzas claros para:

* Bordas
* Cards
* Divisores
* Campos desabilitados

Cinzas escuros para:

* Textos
* Ícones
* Títulos

## Estados

Sucesso

* Verde

Aviso

* Amarelo

Erro

* Vermelho

Informação

* Azul

---

# Tipografia

Utilizar a tipografia padrão do PO-UI.

Priorizar:

* Legibilidade
* Alto contraste
* Tamanho confortável para leitura em tablets

Evitar fontes customizadas.

---

# Espaçamento

Utilizar espaçamento consistente.

Preferência:

* 8px
* 16px
* 24px
* 32px

Nunca posicionar componentes muito próximos.

---

# Layout

Todas as telas deverão possuir:

* Cabeçalho
* Área principal
* Área de ações
* Rodapé opcional

O conteúdo deve permanecer centralizado e organizado.

---

# Cabeçalho

O cabeçalho deve conter:

* Logo Cortag
* Nome da funcionalidade

Sempre manter altura consistente.

---

# Botões

Tipos permitidos:

* Primário
* Secundário
* Perigo
* Link

O botão primário deve utilizar a cor vermelha institucional.

---

# Campos

Todos os campos devem utilizar componentes PO-UI.

Priorizar:

* po-input
* po-select
* po-number
* po-datepicker
* po-checkbox

Campos obrigatórios devem ser claramente identificados.

---

# Tabelas

Utilizar po-table.

As tabelas devem:

* possuir boa legibilidade
* permitir seleção quando necessário
* utilizar zebra quando apropriado
* suportar scroll vertical

---

# Cards

Utilizar cards para agrupar informações relacionadas.

Evitar excesso de bordas.

---

# Ícones

Priorizar ícones do PO-UI.

Os ícones devem representar claramente sua ação.

---

# Loading

Toda operação assíncrona deve apresentar indicador visual de carregamento.

Nunca deixar o usuário sem feedback.

---

# Notificações

Utilizar notificações do PO-UI para:

* sucesso
* erro
* aviso
* informação

Mensagens devem ser objetivas.

---

# Modal e Painéis

Sempre que possível utilizar:

* po-modal
* po-page-slide

Evitar abrir novas páginas quando uma ação puder ser realizada em painel lateral.

---

# Responsividade

O sistema é otimizado para tablets.

Resoluções prioritárias:

* 1024x768
* 1280x800
* 1366x768

Priorizar orientação horizontal.

---

# Usabilidade

Toda interface deve ser pensada para operação por toque.

Portanto:

* botões grandes
* campos altos
* boa área clicável
* pouco texto
* navegação simples

---

# Acessibilidade

Garantir:

* contraste adequado
* foco visível
* mensagens claras
* navegação consistente

---

# Padrões Visuais

Sempre utilizar:

* fundo branco
* destaque em vermelho Cortag
* bordas discretas
* ícones consistentes
* alinhamento uniforme

Evitar:

* gradientes
* sombras excessivas
* animações desnecessárias
* cores diferentes da identidade visual

---

# Componentes PO-UI Preferenciais

* po-page-default
* po-toolbar
* po-input
* po-select
* po-number
* po-button
* po-table
* po-checkbox
* po-page-slide
* po-modal
* po-loading
* po-notification
* po-divider

---

# Princípios para Agentes de IA

Ao implementar qualquer tela, o agente deve:

* Seguir este Design System.
* Não inventar novas cores.
* Não alterar a identidade visual.
* Utilizar componentes PO-UI sempre que possível.
* Priorizar legibilidade e simplicidade.
* Otimizar a interface para tablets.
* Manter consistência entre todas as telas do sistema.

---

# Checklist

Antes de concluir qualquer tela, verificar:

* Identidade visual da Cortag aplicada.
* Componentes PO-UI utilizados.
* Interface otimizada para tablet.
* Espaçamentos consistentes.
* Tipografia padronizada.
* Botões e campos seguindo o Design System.
* Estados de loading, erro e sucesso implementados.
* Layout consistente com as demais telas.
