# 01-aplicacao.md

# Plano de Controle CQ — Visão Geral da Aplicação

## Objetivo

Este documento apresenta a visão geral do sistema **Plano de Controle CQ**, desenvolvido para a **Cortag**, servindo como contexto principal para arquitetos, desenvolvedores e agentes de IA responsáveis pela implementação do projeto.

Todas as funcionalidades do sistema devem seguir as diretrizes descritas neste documento, bem como os documentos complementares do projeto.

---

# Sobre o Sistema

O Plano de Controle CQ é um sistema utilizado no ambiente industrial para apoiar o processo produtivo, permitindo que operadores, líderes e supervisores registrem informações da produção, realizem inspeções de qualidade, apontem paradas, registrem refugo e acompanhem o controle do processo produtivo.

O sistema será integrado ao ERP **TOTVS Datasul** através de APIs, que serão responsáveis pelo fornecimento e persistência das informações.

O foco principal da aplicação é oferecer uma interface simples, rápida e confiável para utilização em tablets industriais durante a operação da fábrica.

---

# Público-Alvo

O sistema será utilizado pelos seguintes perfis:

* Operadores de produção
* Líderes de equipe
* Supervisores
* Inspetores da qualidade
* Administradores do sistema

Cada perfil poderá possuir permissões específicas conforme regras definidas pelo Datasul.

---

# Objetivos da Aplicação

Os principais objetivos do sistema são:

* Facilitar o apontamento da produção.
* Reduzir o tempo gasto em registros operacionais.
* Garantir rastreabilidade das informações.
* Melhorar o controle da qualidade.
* Integrar as operações ao ERP Datasul.
* Oferecer uma interface intuitiva para uso em tablets.

---

# Fluxo Geral da Aplicação

O fluxo principal da aplicação é:

```text
Login

↓

Menu Principal

↓

Equipes

↓

Centro de Trabalho

↓

Reporte de Operações

↓

Reporte de Paradas

↓

Plano de Controle CQ
```

Cada funcionalidade possui seu próprio fluxo interno, documentado em arquivos específicos.

---

# Funcionalidades

O sistema é composto pelos seguintes módulos:

## Login

Responsável pela autenticação do usuário.

---

## Menu Principal

Centraliza o acesso às funcionalidades disponíveis para o usuário autenticado.

---

## Equipes

Permite consultar e manter equipes de produção, bem como seus operadores.

---

## Centro de Trabalho

Permite selecionar o centro de trabalho e o operador responsável pela operação.

---

## Reporte de Operações

Permite iniciar, finalizar e acompanhar ordens de produção.

---

## Reporte de Paradas

Permite registrar paradas ocorridas durante o processo produtivo.

---

## Plano de Controle CQ

Permite realizar inspeções de qualidade conforme o plano de controle da produção.

---

# Fluxo de Autenticação

1. Usuário informa login e senha.
2. O sistema autentica utilizando a API do Datasul.
3. Em caso de sucesso, o usuário é direcionado ao Menu Principal.
4. Em caso de falha, uma mensagem amigável deve ser apresentada.

---

# Fluxo de Navegação

Após autenticação:

```text
Login

↓

Menu Principal

├── Equipes
├── Centro de Trabalho
├── Reporte Operações
├── Reporte Paradas
└── Plano Controle CQ
```

A navegação deve ser simples, rápida e adequada para operação em ambiente industrial.

---

# Integração

Toda comunicação com o ERP será realizada através de APIs.

A aplicação não deverá conter regras de negócio específicas do ERP; essas regras devem permanecer centralizadas na camada de serviços.

---

# Plataforma

A aplicação será desenvolvida utilizando:

* Angular
* TypeScript
* PO-UI
* SCSS

A arquitetura deverá seguir os padrões definidos em `04-arquitetura.md`.

---

# Plataforma de Uso

O sistema será utilizado prioritariamente em tablets industriais.

Características esperadas:

* Operação por toque.
* Uso em orientação horizontal.
* Interface limpa.
* Componentes grandes.
* Alto contraste.
* Boa legibilidade.

---

# Navegação

A navegação deve minimizar o número de cliques necessários para concluir cada operação.

Sempre que possível, utilizar:

* Painéis laterais.
* Modais.
* Confirmações rápidas.

Evitar abrir novas páginas quando uma ação puder ser realizada na mesma tela.

---

# Experiência do Usuário

A aplicação deve priorizar:

* Rapidez.
* Simplicidade.
* Consistência visual.
* Baixa curva de aprendizado.
* Feedback imediato para todas as ações.

---

# Estados da Aplicação

Todas as funcionalidades devem contemplar os seguintes estados:

* Inicial
* Carregando
* Sucesso
* Erro
* Sem dados

Nenhuma operação deve deixar o usuário sem feedback visual.

# Checklist

Antes de iniciar a implementação de qualquer funcionalidade, verificar:

* O Design System foi seguido.
* A arquitetura do projeto foi respeitada.
* O fluxo de navegação foi compreendido.
* A funcionalidade possui documentação específica.
* A implementação está preparada para integração com a API do Datasul.
* A interface está otimizada para tablets.
* O código segue os padrões definidos para o projeto.
